## Contract
- Four players at level 2, 4-hour Deadmines one-shot, 40% story and 60% comedy.
- **Core engine ruleset stays `2024`**; `dlcId = "wow-2026"` is an additive identity, never a third value in legacy `ruleset`. This is required because the current creator deserializer maps non-2014 rulesets back to 2024.
- Player selects WoW or 5R species rules as a single exclusive mechanical source.
- The official WoW book presents 13 class identities as adapters to PHB 2024 core classes, not 13 wholly unrelated base engines. `WOW_BASE_CLASS_IDS` carries the public-safe mapping; it does not supply paid class mechanics.
- **Lv2 hero class gate:** Death Knight (Paladin) and Demon Hunter (Ranger) normally start at level 3 or higher and require an authenticated, campaign/character/class-specific GM waiver **plus subclass choice locked at creation** for Lv1–2. Evoker (Sorcerer) normally begins at level 3; this P0 gate does **not** silently allow a Lv2 Evoker even with a self-declared waiver. Off-race hero-class exceptions are separate DM rulings and still require source-aligned validation.
- Special 5R species require an explicit GM approval outcome scoped to **campaign ID + character ID + species option ID**. Approval for one player must not authorize another player or another campaign.
- 5R equivalence is narrative only and never grants a second set of species traits.
- All paid WoW descriptions, mechanics, level-up tables and class/spell effects stay in private authorized source. A public GitHub Pages script must not contain them.
- The private P0 producer must supply the complete pinned official inventory (source SHA + stable IDs for eight categories) plus per-item `zh-TW` source-bound translation SHA, semantic/mechanics/visible-text PASS evidence. Any missing/duplicate/UNCERTAIN/unexpected/stale entries are BLOCKED. CI synthetic fixtures only prove the validator, not the truth of real translations.
- **Native Item dependency gate:** the P0 inventory also needs nonempty `itemDependencies` generated from official source `@Embed`/`@UUID` references, carrying native pack Item IDs, source SHA, and valid `referencedBy` Journal keys. Every native Item must have its own separate `itemApprovals` entry with source SHA, zh-TW translation SHA, semantic/mechanics/visible-text PASS. A translated Journal page alone never satisfies a referenced Item's rule coverage. Empty `feat` or `spell` categories are blocked for this Lv2 P0 release.
- The user-provided `dnd-world-warcraft.book.json` is **secondary-only**. Its name-keyed pages are useful for private pretranslation and reference discovery but lack the native Item text and stable Journal page identifiers needed to certify the live Foundry pack. Never commit paid text or reconstructed reference data to public GitHub. Owner lease, actual module snapshot, and trusted producer QA are mandatory.
- GM approvals must originate from authenticated authority and be rechecked server-side on save/share/import. A browser Map/Set, client JSON, or UI badge cannot serve as authorization.
- The release gate remains closed until verified licensed delivery, owner leases, source-bound full Traditional Chinese semantic QA, mechanics parity, functional site integration, real browser + Foundry GM Live-UAT, and post-deploy readback.

1. Private provider resolves stable IDs and ruleset source without spoofing GM approval.
2. All available species/class/background/feat/spell/gear level 1–2 entries have complete Taiwan Traditional Chinese display and mechanics checks.
3. Edition-independent compatibility: save/reload, export/import JSON, PDF, class resources, spell slots, ability scores, Foundry bridge.
4. Four level-2 real-player test characters, both source types, GM denial and approval cases.
5. No regressions to 2014/2024 default creation. No public paid content leakage.
6. No main edit, merge or Pages deployment before explicit release checks.
